## PRD Format

User stories are defined in `.nax/features/<name>/prd.json`:

```json
{
  "feature": "user-auth",
  "userStories": [
    {
      "id": "US-001",
      "title": "Add login endpoint",
      "description": "POST /auth/login with email/password",
      "acceptanceCriteria": [
        "Returns JWT on success",
        "Returns 401 on invalid credentials"
      ],
      "tags": ["auth", "security"],
      "status": "pending",
      "routing": {
        "complexity": "medium",
        "testStrategy": "three-session-tdd",
        "reasoning": "Auth endpoint — security override"
      }
    }
  ]
}
```

> **Note:** Use `"status": "passed"` to manually mark a story complete. The loader also normalises the aliases `"done"` → `passed` and `"open"` → `pending`.

`nax plan` also writes envelope fields (`project`, `branchName`, `createdAt`, `updatedAt`) and run-tracking fields on each story (`passes`, `attempts`, `escalations`, `priorErrors`, …). You rarely need to edit those by hand; missing `tags`, `dependencies`, `status`, and `acceptanceCriteria` default to empty/`pending` on load.

---

### Field Reference

| Field | Type | Required | Description |
|:------|:-----|:--------|:------------|
| `feature` | `string` | Yes | Feature name (should match folder name) |
| `userStories` | `array` | Yes | Array of user story objects |
| `outOfScope` | `array` | No | Feature-level exclusions carried from the spec's "Out of Scope" / "Non-Goals" section; mirrored onto every story at load time |
| `id` | `string` | Yes | Unique story identifier (e.g., "US-001") |
| `title` | `string` | Yes | Short story title |
| `description` | `string` | No | Detailed description of the story |
| `acceptanceCriteria` | `array` | Yes | List of criteria that must be met |
| `suggestedCriteria` | `array` | No | Planner-suggested criteria beyond the spec — tested in the post-run hardening pass, never block the pipeline |
| `complexity` | `string` | No | **Legacy.** Use `routing.complexity` instead |
| `tags` | `array` | No | Tags for keyword routing and classification |
| `status` | `string` | No (defaults to `pending`) | Story status: `pending`, `in-progress`, `passed`, `failed`, `skipped`, `blocked`, `paused`, `regression-failed`, `decomposed` |
| `workdir` | `string` | No | Package directory (relative to repo root) for monorepos |
| `workdirSource` | `string` | No | How `nax plan` chose `workdir`: `stated`, `derived`, or `defaulted` (`defaulted` means root rules and root `quality.commands` apply) |
| `dependencies` | `array` | No | Array of story IDs this story depends on |
| `contextFiles` | `array` | No | Files loaded into the agent prompt before execution (replaces deprecated `relevantFiles`) |
| `expectedFiles` | `array` | No | Files that must exist after execution (opt-in pre-flight gate) |
| `modifiedFiles` | `array` | No | Existing files the story is authorised to change, extracted from the spec's `### Modifies` section |
| `outOfScope` | `array` | No | Story-specific exclusions (plus the mirrored feature-level list) |
| `priority` | `number` | No | Scheduling priority (higher = sooner, default 0); set via the `PRIORITY` queue command |
| `parentStoryId` | `string` | No | Set on sub-stories created by decomposition |
| `routing` | `object` | No | Routing decisions — **always generated by `nax plan`** |
| `routing.complexity` | `string` | No | `simple`, `medium`, `complex`, `expert` |
| `routing.testStrategy` | `string` | No | `no-test`, `tdd-simple`, `three-session-tdd-lite`, `three-session-tdd`, `test-after` |
| `routing.reasoning` | `string` | No | Brief classification rationale |
| `routing.noTestJustification` | `string` | No | Required when `testStrategy` is `no-test` |
| `routing.agent` | `string` | No | Agent assigned at plan time (overrides the default agent; see ADR-025) |

> **PRD routing always wins.** When `routing.complexity` and `routing.testStrategy` are present (which `nax plan` always generates), runtime routing (keyword/LLM/plugin) is skipped entirely. To change routing for a story, edit these fields directly in `prd.json` before running `nax run`.
