# Issue #1514 Phase 3 — Test Typecheck Ratchet + Factory Extensions Design

> **Status:** Drafted 2026-08-10. Approved by william khoo during session.
> **Scope:** Phase 3a (ratchet infrastructure) + 3b (factory extensions to first error floor).
> **Out of scope:** 3c per-file burn-down (curator-heuristics, parallel-batch, etc.) and Phase 4 (wiring `tsconfig.test.json` into top-level `typecheck`) — separate branches.

## Problem

`tsconfig.test.json` covers `test/**` and `scripts/**`. After Phase 2 (PR #1539, merged), `scripts/` typechecks clean. `test/` still reports **2148 errors across 417 files** because the test tree has never been typechecked.

The errors are overwhelmingly **fixture drift**: when a required field is added to a type, the test helpers and consumer tests are never updated. The dominant root causes (per issue #1514):

| Missing property | Count | Targets |
|:--|--:|:--|
| `statusFile` (`RunOptions`) | 22 | `runner-setup`, `runner-execution`, `runner-completion` |
| `sourceDiffCap` (`nbfRectify`) | 20 | non-blocking-fix tests |
| `resolution` | 20 | `ResolvedTestPatterns` |
| `preconnect` | 19 | routing / observation tests |
| `projectKey` | 12 | context-bundle / project-view |
| `getAdvisoryFindings` | 11 | review auditor mocks |

Concentration is favourable for incremental work — top 6 properties clear 104 errors, and extending 25 existing factory helpers (which cover `Observation`, `RunAsSessionOverrideFn`, `FindingSource`, `NonBlockingFixArgs`, `PipelineContext`, `RunOptions`, `ContextBundle`, `ReviewAuditor`) propagates fixes to consumer tests.

The risk is invisible debt: a strict gate landed on 2148 errors invites the path of least resistance (more `as unknown as` casts) and leaves the repo worse than today. The current `as unknown as` count is **824** and growing (issue measured 807). The ratchet must prevent it absorbing the work.

## Approach

Two ratchets, one PR:

1. **`check:test-typecheck`** — counts `error TS\d+` matches in `tsconfig.test.json`'s output; fails if the count grows.
2. **`check:test-as-unknown-as`** — counts `as unknown as` occurrences in `test/**/*.ts`; fails if the count grows.

Both follow the existing `check-nax-error.ts` / `check-deep-relatives.ts` pattern: same `Baseline` interface (`{ count, updatedAt, byFile? }`), same `--update-baseline` and `--list` flags, same fail-on-growth-only semantics, baselines stored under `scripts/baselines/<name>-baseline.json`.

After the ratchets land green-on-current-state, **factory extensions** propagate fixture corrections. Each factory-extension commit should reduce the typecheck-error ratchet's number without growing the cast ratchet.

## Architecture

```
scripts/check-test-typecheck.ts          # spawn tsc + parse, exports countErrorOutput/formatReport
test/unit/scripts/check-test-typecheck.test.ts  # tests parser + ratchet logic; no real tsc spawn
scripts/baselines/test-typecheck-baseline.json   # initial: 2148 errors

scripts/check-test-as-unknown-as.ts       # glob test/ + grep, exports scanForCasts/formatReport
test/unit/scripts/check-test-as-unknown-as.test.ts
scripts/baselines/test-as-unknown-as-baseline.json  # initial: 824 casts

package.json:
  check:test-typecheck             → bun run scripts/check-test-typecheck.ts
  check:test-typecheck:update      → ... --update-baseline
  check:test-as-unknown-as         → bun run scripts/check-test-as-unknown-as.ts
  check:test-as-unknown-as:update  → ... --update-baseline
  check:all                        → ... && bun run check:test-typecheck && bun run check:test-as-unknown-as && ...
```

### Why two ratchets, not one combined gate

Issue #1514 explicitly requires both counts to ratchet, and combining them into one script loses per-axis attribution. When the cast ratchet fires, we want to know "this PR added 12 casts in these files", not "something grew". Two scripts with their own `--list` output is the standard way this codebase already handles dual-axis ratchets.

### Why baselines at current state (2148 / 824), not at zero

Zero-error baselines would require fixing every error before the gate can ever turn green (a flag day). Recording current counts as the baseline makes the gate a ratchet: passes on initial land, fails only on regression, allows progressive reduction via `--update-baseline` as commits land. This matches the established pattern (see `check-nax-error`, `check-deep-relatives`).

### Allow-list escape hatch (deferred)

If a genuinely unavoidable `as unknown as` appears (e.g. `... as unknown as Partial<T>` for partial mocks), we'll add `// test-ratchet-allow: as-unknown-as` mirroring the existing `// nax-lint-allow: plain-error` marker. **Not added in this PR** — only if a wave gets stuck.

## Factory Waves (3b)

Sequenced by issue-listed missing-property counts. Each wave is a small cluster of commits:

| Wave | Property added | Factory helper touched | Consumer impact |
|:--|:--|:--|:--|
| 1 | `statusFile` | `test/helpers/runtime.ts`, `mock-nax-config.ts` | runner-setup/execution/completion tests |
| 2 | `sourceDiffCap` | non-blocking-fix factory (TBD location) | fix-target tests |
| 3 | `resolution` | `test/helpers/e2e/orchestrator-harness.ts` | clears harness's own errors first |
| 4 | `preconnect` | routing-context factory | observation / routing tests |
| 5 | `projectKey` | `ContextBundle` / `ProjectView` factory | context-bundle consumers |
| 6 | `getAdvisoryFindings` | `mock-agent-manager.ts` / review-auditor factory | review-audit tests |

**Commit granularity within a wave:**
1. Add the property to the factory (typed correctly — no `as unknown as` growth).
2. Update the factory's own tests (use the new property).
3. Update dominant consumer tests (replace ad-hoc objects with factory call).
4. Re-run `bun x tsc --project tsconfig.test.json --noEmit` to verify count dropped.
5. Commit with body noting "typecheck errors: N → M".

We do **not** run `check:test-typecheck:update` mid-wave — that would hide pre-existing errors. The baseline drops only at the **end of the PR**, when we know the wave-commits collectively reduced the count.

## Verification Strategy

Before PR:

1. `bun run build` — pass
2. `bun run typecheck` — pass (no regression on src/)
3. `bun run lint` — pass
4. `bun run check:all` — pass (both new ratchets included)
5. `bun test test/unit/ --bail --timeout=60000` — all existing 12,453 tests still pass
6. `bun run check:test-typecheck:update && bun run check:test-as-unknown-as:update && git diff scripts/baselines/` — confirm baselines shrank (i.e. 3b did real work)
7. Capture before/after: `bun x tsc --project tsconfig.test.json --noEmit 2>&1 | wc -l` should be meaningfully < 2148 (target: ≤ 1500, ideally ≤ 1100)

## Commit Boundaries (one PR, multiple commits)

```
chore(test-debt): scaffold check-test-typecheck ratchet (script + tests)
chore(test-debt): scaffold check-test-as-unknown-as ratchet (script + tests)
ci: wire test ratchets into check:all (no baselines → CI red)
chore(test-debt): seed ratchet baselines at current counts (CI green)
fix(factories): add statusFile to run-options factory
fix(factories): wire statusFile in runner tests
fix(factories): add sourceDiffCap to nbfRectify factory
... (more factory waves)
chore(test-debt): lower ratchet baselines to committed reduction
docs(scripts): document the two test ratchets in .claude/rules/
docs(plan): add phase 3 plan doc
```

The "CI red → CI green → shrink" rhythm makes the ratchet's purpose visible in the PR diff.

## Risks

- **Wave estimates optimistic.** If `statusFile` setter propagates through 30+ tests that all set it ad-hoc, wave 1 will balloon. Mitigation: split waves 1-3 into "factory extension" + "consumer rewrite" PRs if any single wave exceeds ~15 commits.
- **`as unknown as` ratchet may over-fire.** Some legitimate uses (test mocks of `Partial<T>`) shouldn't grow the count. The allow-list escape hatch is designed but not built — flip it on only if needed.
- **`check:gate-reachability` exemption list.** Existing scripts that the gate reachability test considers may need their paths updated if the gate considers the new `check:*` scripts as "added but unreached". Will address in the wire-up commit if it fails.

## What This Does NOT Do

- Does not wire `tsconfig.test.json` into top-level `typecheck` (Phase 4). That gate activation only makes sense when errors reach ~0.
- Does not burn down to zero. The PR ships when factory fixes are committed and the error-count demonstrably falls (target: ≤1500 from 2148, ideally ≤1100). The ratchet allows further shrinkage in 3c PRs.
- Does not address `as unknown as` counts growing elsewhere — only ratchets them.
- Does not modify `scripts/check-gate-reachability.ts` unless reachability tests fail.

## Out of Scope (separate branches)

- **3c.** Per-file burn-down of top-error files (`test/unit/plugins/builtin/curator-heuristics.test.ts` 38 errors, `parallel-batch.test.ts` 36, etc.). Multiple PRs.
- **Phase 4.** Wire `tsconfig.test.json` into `typecheck` script. Single PR, lands once errors ~0.
