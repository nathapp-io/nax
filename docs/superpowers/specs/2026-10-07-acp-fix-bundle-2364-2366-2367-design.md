## 2. #2366 — read-only without plan mode

### 2.1 Why plan mode goes

S4 §6.4 layer 1 used Claude's `plan` mode as the agent-side backstop for `none`/`read`. Live evidence shows it is not one, and it costs workarounds:

- plan mode writes `~/.claude/plans/<slug>.md` without a `session/request_permission` (#2366);
- refused writes route through `ExitPlanMode`, whose reject the adapter turns into an interrupt (`ACP_STOP_CANCELLED`), so it had to be disallowed (#2365);
- plan mode asks before any MCP tool not marked `readOnlyHint`, so every embedder tool was marked read-only (#2365) — a false claim about tools that may write.

Removing the write tools is stronger than a mode: the agent cannot call a tool it was not given.

### 2.2 Registry shape

`AgentRegistryEntry` (`src/client/registry.ts`) replaces `readOnlyMode: ModeSetting | undefined` and `defaultMode: ModeSetting | undefined` with:

```ts
interface ReadOnlyEnforcement {
  /** The mode set for none/read (Claude: config option `mode` = `default`). */
  readonly mode: ModeSetting;
  /** Agent tools removed from the session under none/read. */
  readonly disallowedTools: readonly string[];
}

interface AgentRegistryEntry {
  // ...
  readonly readOnly: ReadOnlyEnforcement | undefined;
  /** The mode set for ask/full (Claude: `default`). */
  readonly defaultMode: ModeSetting | undefined;
}
```

Claude's entry: `readOnly = { mode: { configId: "mode", value: "default" }, disallowedTools: ["Write", "Edit", "MultiEdit", "NotebookEdit"] }`, `defaultMode` unchanged. All other agents: `readOnly: undefined`.

`disallowedTools` is applied through the agent's pre-approval channel (`claudeCode.allowedTools` kind for Claude, `_meta.claudeCode.options.disallowedTools`). An entry whose pre-approval kind cannot carry tool removal must not declare `disallowedTools` — the registry test asserts this.

### 2.3 Behaviour

- `capabilities.ts`: enforceability checks `entry?.readOnly !== undefined`; the mode for `none`/`read` is `entry.readOnly.mode`. The public capability record keeps its field `readOnlyMode: boolean` (meaning "none/read are enforceable"); consumers see no change.
- `pre-approval.ts`: `claudeSessionMeta` takes the entry's `readOnly.disallowedTools` under `none`/`read` instead of the module constant. `READ_ONLY_DISALLOWED_TOOLS` and the `ExitPlanMode` rationale are deleted.
- `tool-calls.ts`: the `annotations: { readOnlyHint: true }` on every embedder tool is removed. Embedder tools stay pre-approved by the exact `mcp__nax__<tool>` rules (R12), which is all `default` mode needs.
- Layer 2 (`permissions.ts`) is unchanged: `none`/`read` reject every request with `decidedBy: "profile"`. Bash is kept for reads; a Bash command Claude's `default` mode does not treat as read-only asks first and is rejected.
- Resume: the `_meta` changes (`disallowedTools` content, mode), so resuming a session created under 0.3.0 with `none`/`read` may rebuild Claude's agent session. The README already documents that `_meta` changes can do this.

### 2.4 Guarantee, restated

Under `none`/`read` with Claude: no built-in write tool exists; every action Claude asks about is refused. Claude may still run tools it does not ask about (reads, search, read-only Bash) and writes its own state (transcripts). There is no plan file, because plan mode is not entered.

### 2.5 Docs

- `packages/nax-agent-acp/README.md` profile table: Claude agent mode for `none`/`read` becomes `default` + removed write tools; the `ExitPlanMode` and plan-file bullets are replaced by the restated guarantee (§2.4).
- S4 spec §6.4 table and the R12 #2365 amendment: annotated "superseded by the 2026-10-07 fix bundle".

### 2.6 Follow-up issue (filed with the PR)

"nax-agent-acp: `none`/`read` for codex and opencode" — codex-acp exposes approval and sandbox modes as config options (Codex's read-only sandbox is OS-enforced); opencode has a permission config. Each needs an adapter-source check and a live run. Gemini (MCP permission requests lack tool identity) and pi (local fs/shell, no delegation) are noted as not viable today.

## 3. #2367 — errored and cancelled turns keep their spend

### 3.1 Today

- `turn.ts` `resultOf` calls `collector.settle(response)` before throwing `stopReasonError` for a non-`end_turn` stop. The usage event is emitted and the cost meter's baseline advances, so the next turn cannot recover the cost; the thrown `NaxError` carries no spend, so the facade's `spendOf()` returns 0. The cost is lost, not deferred.
- The abort path (`cancelTurn`) never settles the collector: no usage event, and `beginTurn()` on the next turn forgets the reading while the baseline stays, so the cost lands on the next priced turn (or nowhere, if the session ends).
- `agent-session-turn.ts` `fromError()` never sets `costSource`.

### 3.2 nax-agent (additive)

- New in `src/session/turn-spend.ts`, exported from `.`:

  ```ts
  export interface FailedTurnSpend {
    readonly tokenUsage: TokenUsage;
    readonly costUsd: number;
    readonly costSource?: CostSource;
  }
  /** Attaches the spend a failed turn had already incurred to the error it throws. */
  export function attachTurnSpend(err: object, spend: FailedTurnSpend): void;
  export function readTurnSpend(err: unknown): FailedTurnSpend | undefined;
  ```

  `CostSource` (`agent-session-types.ts`) is the type `turn_end.costSource` already uses; `FailedTurnSpend` avoids clashing with nax-agent-acp's own `TurnSpend`. The WeakMap moves here; `recordNativeTurnFailureUsage` / `readNativeTurnFailureUsage` in `native/session/turn-types.ts` become thin wrappers (no native behaviour change).
- `fromError()` spreads `costSource` when the attached spend has one. `spendOf()` reads `readTurnSpend` first, then the existing `SessionTurnError` fields, then zero.

### 3.3 nax-agent-acp

- `turn.ts` `resultOf`: on a non-`end_turn` stop, build the `stopReasonError`, `attachTurnSpend(error, spend)`, throw it. Error code and message are unchanged.
- `turn.ts` abort path: `cancelTurn` returns the settled response when it arrives within `cancelGraceMs`. `runPromptTurn` then calls `collector.settle(response)` (usage event out, baseline advanced) and attaches the spend to the error it throws. The thrown error is the turn signal's reason, an object owned by that turn's `AbortController`, so attaching to it cannot leak across turns. When the grace expires (process killed), nothing is settled: the turn stays unpriced and the baseline does not move, as today.
- nax-agent-acp's `TurnSpend` (`usage.ts`) already has this shape and is passed as a `FailedTurnSpend` (`tokenUsage`, `costUsd`, `costSource`).

Result: an errored or cancelled turn's `turn_end` carries the usage and cost the turn's `usage` event reported, with `costSource`, exactly as a completed turn does.

## 4. #2364 — instructions marked delivered on receipt

- `backend.ts` `sendTurn` no longer sets `s.instructionsSent = true` before the prompt.
- `createTurnCollector` gains an option `onReceipt?: () => void`, called at most once: on the first `onUpdate` routed while the collector is open (any `sessionUpdate` kind), or in `settle(response)` (any stop reason). `sendTurn` passes `onReceipt` only when this turn carries the instructions, and it sets `s.instructionsSent = true`.
- A turn that ends before either signal — agent gone (`agentGoneError`), JSON-RPC error response, or an abort whose grace expired with no update — leaves the flag false; the next `send()` (after `reconnect()` where needed) prepends the instructions again.
- Initial value is unchanged: a resumed session with a turn marker starts `true` (D6-f).

Accepted edge: an agent that received the prompt but died before emitting anything gets the instructions twice after reconnect. Duplicate beats loss (F5).

## 5. Testing

Test-first, in the existing suites (`packages/nax-agent-acp/test/unit/client/`, fake agent under `test/unit/fake-agent/`, nax-agent `test/unit/session/`).

- **nax-agent unit:** `attachTurnSpend`/`readTurnSpend` round trip; native wrappers still read what they wrote; `fromError` with attached spend (`errored` and `cancelled` statuses) carries usage, cost and `costSource`; without it, zero as before.
- **nax-agent-acp unit:**
  - registry: Claude has `readOnly` with the four tools and mode `default`; no other agent has `readOnly`; `none`/`read` still `CAPABILITY_UNSUPPORTED` for them.
  - `claudeSessionMeta`: `none`/`read` → `disallowedTools` = the four tools, no `ExitPlanMode`; `ask`/`full` → none.
  - tool host list has no `readOnlyHint`.
  - collector: `onReceipt` fires once on first update, once on settle, never after finish without either.
- **Fake agent:**
  - dies before the prompt arrives → reconnect → the next prompt text starts with the instructions;
  - streams an update then dies → reconnect → no instructions on the next prompt;
  - stop reason `cancelled` with a `usage_update` → `turn_end` `errored`/`ACP_STOP_CANCELLED` with the reported cost, tokens and `costSource: "reported"`; next turn's cost is its own delta;
  - `cancel()` with the response inside the grace → `turn_end` `cancelled` with the cost; grace expired → unpriced, baseline unchanged.
- **Live Claude check (billed, under $1, approval at launch):** packed tarballs, `profile: "read"`, Claude `sonnet`, a session with one embedder tool:
  1. "create a file named created.txt containing hello" → no file in the workdir, no new file under `~/.claude/plans/`, turn completes (not `ACP_STOP_CANCELLED`);
  2. the embedder tool runs without a permission request;
  3. a read ("list the files here") works.
  Record the cost and any `decidedBy: "profile"` denials (counted, not required).
- Gates: `typecheck`, `check:all`, `bun run test` at the repo root.
