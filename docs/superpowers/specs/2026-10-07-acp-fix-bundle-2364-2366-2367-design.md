# ACP fix bundle: #2364, #2366, #2367 — design

- **Date:** 2026-10-07 (revised after spec review the same day)
- **Packages:** `@nathapp/nax-agent` (additive export), `@nathapp/nax-agent-acp`
- **Issues:** #2364 (instructions lost before first delivery), #2366 (Claude plan-file write under `none`/`read`), #2367 (errored/cancelled turn reports cost 0)
- **Parent spec:** `2026-10-05-s4-acp-backend-design.md` (§6.3, §6.4, §6.6, §6.7, R12)
- **Ships as:** one PR; nax-agent 0.3.1 + nax-agent-acp 0.3.1, a lockstep patch pair (acp needs nax-agent >= 0.3.1 for `attachTurnSpend`). No release without an explicit go.

## 1. Rulings (brainstorm and review, 2026-10-07)

| # | Ruling |
|---|---|
| F1 | #2366: drop Claude plan mode. `none`/`read` on Claude run in mode `default` with the built-in write tools and `EnterPlanMode` removed (`disallowedTools`); layer 2 still rejects every permission request. |
| F2 | #2366: the registry's `readOnlyMode` becomes one per-agent read-only enforcement entry, so codex/opencode can be added later without a redesign. Only Claude gets an entry now; a follow-up issue covers codex (read-only sandbox) and opencode (permission config). |
| F3 | #2367: nax-agent exports `attachTurnSpend(err, spend)`, built on the existing failure-usage WeakMap that the facade's `spendOf()` already reads; `turn_end` from an error also carries `costSource`. |
| F4 | #2367: the abort path (`cancel()`, turn timeout, `close()`) is included: a response that arrives within `cancelGraceMs` is settled and its spend attached. |

## 2. #2366 — read-only without plan mode

### 2.1 Why plan mode goes

S4 §6.4 layer 1 used Claude's `plan` mode as the agent-side backstop for `none`/`read`. Live evidence shows it is not one, and it costs workarounds:

- plan mode writes `~/.claude/plans/<slug>.md` without a `session/request_permission` (#2366);
- refused writes route through `ExitPlanMode`, whose reject the adapter turns into an interrupt (`ACP_STOP_CANCELLED`), so it had to be disallowed (#2365);
- plan mode asks before any MCP tool not marked `readOnlyHint`, so every embedder tool was marked read-only (#2365), a false claim about tools that may write.

Removing the write tools is stronger than a mode: the agent cannot call a tool it was not given.

### 2.2 Why settings are not loaded (F6)

claude-agent-acp 0.85.1 builds the SDK options with `settingSources: ["user", "project", "local"]` and then spreads `_meta.claudeCode.options` over them (`dist/acp-agent.js:6827`), so `_meta` can override it. With settings loaded:

- `permissions.allow` rules (for example `Bash(*)`) run matching actions with no `request_permission`, so layer 2 never sees them;
- hooks run shell commands without asking (this hole exists under plan mode today too);
- settings-declared MCP servers add tools outside the profile.

`settingSources: []` removes all three. Costs, accepted: the project's `CLAUDE.md` and settings `env` are not applied under `none`/`read` (session instructions still come from `ctx.instructions`; auth comes from the environment or the keychain). The adapter's own settings reader still picks the spawn-time mode from `permissions.defaultMode`; `allowDangerouslySkipPermissions: false` keeps that from being `bypassPermissions`, and `applyConfig` sets mode `default` before the first prompt.

### 2.3 Registry shape

`AgentRegistryEntry` (`src/client/registry.ts`) replaces `readOnlyMode: ModeSetting | undefined` with:

```ts
interface ReadOnlyEnforcement {
  /** The mode set for none/read (Claude: config option `mode` = `default`). */
  readonly mode: ModeSetting;
  /** Agent tools removed from the session under none/read. */
  readonly disallowedTools: readonly string[];
  /** Extra agent options under none/read, merged into the pre-approval channel's options. */
  readonly sessionOptions: Readonly<Record<string, unknown>>;
}

interface AgentRegistryEntry {
  // ...
  readonly readOnly: ReadOnlyEnforcement | undefined;
  /** The mode set for ask/full (Claude: `default`); unchanged. */
  readonly defaultMode: ModeSetting | undefined;
}
```

Claude's entry:

```ts
readOnly: {
  mode: { configId: "mode", value: "default" },
  disallowedTools: ["Write", "Edit", "MultiEdit", "NotebookEdit", "EnterPlanMode"],
  sessionOptions: { settingSources: [], allowDangerouslySkipPermissions: false },
}
```

All other agents: `readOnly: undefined`. The `entry()` helper's `Pick<...>` parameter changes from `readOnlyMode` to `readOnly`, and it deep-freezes the `readOnly` object, its `disallowedTools` array and `sessionOptions`.

`readOnly` is applied through the agent's pre-approval channel (`claudeCode.allowedTools` kind for Claude: `_meta.claudeCode.options`). An entry whose pre-approval kind is undefined must not declare `readOnly`; the registry test asserts this.

### 2.4 Behaviour

- `capabilities.ts`: enforceability checks `entry?.readOnly !== undefined`; `modeFor` returns `entry.readOnly.mode` for `none`/`read`. The public capability record keeps its field `readOnlyMode: boolean` (meaning "none/read are enforceable"); consumers see no change.
- `pre-approval.ts`: the signature becomes `claudeSessionMeta(kind, toolNames, readOnly: ReadOnlyEnforcement | undefined)`; the caller passes `entry.readOnly` under `none`/`read` and `undefined` under `ask`/`full`. Under `none`/`read` the options are `{ allowedTools?, disallowedTools: readOnly.disallowedTools, ...readOnly.sessionOptions }`. `READ_ONLY_DISALLOWED_TOOLS` and the `ExitPlanMode` rationale are deleted.
- `open.ts` `sessionSetup` (line 185) is the only call site. The `_meta` it builds is used for `session/new`, `session/resume` and `session/load` alike, so restore paths enforce the same options.
- `applyConfig` still calls `session/set_config_option` for the mode, now `default` under every profile. That is wanted on resume: a session saved under 0.3.0 in `plan` is reset to `default`.
- `tool-calls.ts`: the `annotations: { readOnlyHint: true }` on every embedder tool is removed. Embedder tools stay pre-approved by the exact `mcp__nax__<tool>` rules (R12), which is all `default` mode needs; nothing under `ask`/`full` depended on the hint.
- Layer 2 (`permissions.ts`) is unchanged: `none`/`read` reject every request with `decidedBy: "profile"`. Bash is kept for reads; a Bash command Claude's `default` mode does not treat as read-only asks first and is rejected. With no settings loaded, no allow rule can pre-approve it.
- Resume: the `_meta` changes (`disallowedTools`, `settingSources`, mode), so resuming a 0.3.0 `none`/`read` session may rebuild Claude's agent session. The README already documents that `_meta` changes can do this.

### 2.5 Guarantee, restated

Under `none`/`read` with Claude: no built-in file-write tool and no plan mode exist; no user, project or local Claude settings (allow rules, hooks, MCP servers) apply; every action Claude asks about is refused. Claude may still run tools it does not ask about (reads, search, read-only Bash) and writes its own state (transcripts). There is no plan file, because plan mode cannot be entered.

### 2.6 Docs and stale references

- `packages/nax-agent-acp/README.md`:
  - profile table (lines ~95-96): Claude agent mode for `none`/`read` becomes `default`, write tools removed, no settings;
  - the `ExitPlanMode` and plan-file bullets (lines ~106-111) are replaced by the restated guarantee (§2.5) and a note that `none`/`read` ignore Claude settings files;
  - the embedder-tools bullet that says tools are listed read-only (`readOnlyHint`, plan mode; lines ~150-160) is removed.
- Source comments: `pre-approval.ts:8-9`, `tool-calls.ts:182-185`, `permissions.ts:9` (plan-mode wording).
- Tests referencing `readOnlyHint`, `readOnlyMode` (registry field) or `READ_ONLY_DISALLOWED_TOOLS` are updated: tool-host, tool-calls, pre-approval, registry, capabilities, open, resume, backend suites.
- S4 spec §6.4 table and the R12 #2365 amendment: annotated "superseded by the 2026-10-07 fix bundle".

### 2.7 Follow-up issue (filed with the PR)

"nax-agent-acp: `none`/`read` for codex and opencode": codex-acp exposes approval and sandbox modes as config options (Codex's read-only sandbox is OS-enforced); opencode has a permission config. Each needs an adapter-source check and a live run. Gemini (MCP permission requests lack tool identity) and pi (local fs/shell, no delegation) are noted as not viable today.

## 3. #2367 — errored and cancelled turns keep their spend

### 3.1 Today

- `turn.ts` `resultOf` calls `collector.settle(response)` before throwing `stopReasonError` for a non-`end_turn` stop. The usage event is emitted and the cost meter's baseline advances, so the next turn cannot recover the cost; the thrown `NaxError` carries no spend, so the facade's `spendOf()` returns 0. The cost is lost, not deferred.
- The abort path (`cancelTurn`) never settles the collector: no usage event, and `beginTurn()` on the next turn forgets the reading while the baseline stays, so the cost lands on the next priced turn (or nowhere, if the session ends).
- `agent-session-turn.ts` `fromError()` never sets `costSource`.

### 3.2 nax-agent (additive)

- New in `src/session/turn-spend.ts`, exported from `src/index.ts` (hand-maintained named exports):

  ```ts
  export interface FailedTurnSpend {
    readonly tokenUsage: TokenUsage;
    readonly costUsd: number;
    readonly costSource?: CostSource;
  }
  /** Attaches the spend a failed turn had already incurred to the error it throws. */
  export function attachTurnSpend(err: object, spend: FailedTurnSpend): void;
  export function readTurnSpend(err: unknown): FailedTurnSpend | undefined;
  ```

  `CostSource` (`agent-session-types.ts:88`) is the type `turn_end.costSource` already uses; `FailedTurnSpend` avoids clashing with nax-agent-acp's own `TurnSpend`.
- The WeakMap moves to `turn-spend.ts`. `recordNativeTurnFailureUsage`, `readNativeTurnFailureUsage` and `NativeTurnFailureUsage` are already public (`api/nax-agent.api.txt`) and stay, as thin wrappers over the new functions; no native behaviour change.
- `spendOf()` returns `{ usage, costUsd, costSource? }`: `readTurnSpend` first, then the existing `SessionTurnError` fields, then zero. `fromError()` spreads it into every branch's base, so `costSource` reaches `errored`, `cancelled`, `timed_out` and the consumer-stalled branch alike.
- The public API snapshot `packages/nax-agent/api/nax-agent.api.txt` is regenerated with `bun run api:update`; `bun run check:api` must pass.

### 3.3 nax-agent-acp

- `turn.ts` `resultOf`: on a non-`end_turn` stop, build the `stopReasonError`, `attachTurnSpend(error, spend)`, throw it. Error code and message are unchanged.
- `turn.ts` abort path:
  - `cancelTurn` returns `PromptResponse | undefined`: the response when the prompt settles `ok` within `cancelGraceMs`; `undefined` on timeout (process killed, session disconnected, as today) and on a `failed` settle.
  - With a response, `runPromptTurn` calls `collector.settle(response)` (the usage event goes out before `turn_end`, baseline advances), then attaches the spend to the error it throws. This holds for any stop reason, `end_turn` included: the turn was aborted, so the abort reason is still thrown.
  - The thrown error is the turn signal's reason or `abortReason`'s fresh `NaxError`; the facade creates a new reason per turn, so attaching cannot leak across turns.
  - Without a response nothing is settled: the turn stays unpriced and the baseline does not move, as today.
  - `close()` aborts concurrently with `shutdown()`, whose `terminate(cancelGraceMs)` may kill the agent before a response arrives; pricing on `close()` is best effort.
- nax-agent-acp's `TurnSpend` (`usage.ts`) already has the `FailedTurnSpend` shape and is passed as one.

Result: an errored or cancelled turn's `turn_end` carries the usage and cost the turn's `usage` event reported, with `costSource`, as a completed turn does.

## 4. #2364 — instructions marked delivered on receipt

- `backend.ts` `sendTurn` no longer sets `s.instructionsSent = true` before the prompt.
- `createTurnCollector` gains an option `onReceipt?: () => void`, called at most once, on the first of:
  - an `onUpdate`, while the collector is open, whose `sessionUpdate` is turn content: `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update`, `usage_update` or `plan` (an allowlist: any other kind, including ones added to the SDK later, is not receipt). Session-level updates (`available_commands_update`, `current_mode_update`, `config_option_update`, `session_info_update`) and replayed history (`user_message_chunk`) are not receipt: Claude emits them after `session/new`, `set_config_option` and `session/load`, so they can arrive after `router.attach` but before the agent reads the prompt;
  - `settle(response)`, for any stop reason.
- `sendTurn` passes `onReceipt` only when this turn carries the instructions; the callback sets `s.instructionsSent = true`.
- A turn that ends before either signal leaves the flag false, and the next `send()` (after `reconnect()` where needed) prepends the instructions again. That covers: agent gone (`agentGoneError`), a JSON-RPC error response (F7), and an abort whose grace expired with no turn-content update.
- Initial value is unchanged: a resumed session with a turn marker starts `true` (D6-f).

Accepted edges (F5, F7): an agent that received the prompt but died before emitting turn content, or answered it with an RPC error after recording it, gets the instructions a second time.

## 5. Testing

Test-first, in the existing suites (`packages/nax-agent-acp/test/unit/client/`, the fake agent under `test/unit/fake-agent/`, nax-agent `test/unit/session/`).

- **nax-agent unit:**
  - `attachTurnSpend`/`readTurnSpend` round trip; the native wrappers still read what they wrote;
  - `fromError` with attached spend carries usage, cost and `costSource` for `errored`, `cancelled`, `timed_out` and consumer-stalled; without it, zero and no `costSource`, as before.
- **nax-agent-acp unit:**
  - registry: Claude has `readOnly` with the five tools, mode `default` and the two session options; every `readOnly` is frozen; no other agent has `readOnly`, and `none`/`read` stay `CAPABILITY_UNSUPPORTED` for them;
  - `claudeSessionMeta`: `none`/`read` → `disallowedTools` = the five tools, `settingSources: []`, `allowDangerouslySkipPermissions: false`, no `ExitPlanMode`; `ask`/`full` → none of these;
  - tool host list has no `readOnlyHint`;
  - collector `onReceipt`: fires once on the first turn-content update; once on settle; once when settle follows finish; never for `available_commands_update`, `current_mode_update` or `user_message_chunk`; never after finish without either;
  - unpriced agent: a failed turn reports `costSource: "unpriced"` and cost 0.
- **Fake agent:**
  - dies before the prompt arrives → reconnect → the next prompt text starts with the instructions;
  - sends `available_commands_update`, then dies before the prompt → the instructions are resent;
  - streams a turn-content update then dies → reconnect → no instructions on the next prompt;
  - answers `session/prompt` with a JSON-RPC error → the next prompt carries the instructions;
  - stop reason `cancelled` with a `usage_update` → `turn_end` `errored`/`ACP_STOP_CANCELLED` with the reported cost, tokens and `costSource: "reported"`; the next turn's cost is its own delta;
  - `cancel()` with the response inside the grace → a `usage` event before `turn_end`, `turn_end` `cancelled` with the cost; grace expired → unpriced, baseline unchanged;
  - resume of a session whose saved `_meta`/mode came from 0.3.0 (`plan`) → mode set to `default`, the read-only `_meta` sent on `session/resume`/`session/load`.
- **Live Claude check (billed, under $1, approval at launch):** packed tarballs, `profile: "read"`, Claude `sonnet`, a session with one embedder tool, run from a workdir whose `.claude/settings.json` allows `Bash(*)`:
  1. "create a file named created.txt containing hello" → no file in the workdir, no new file under `~/.claude/plans/`, turn completes (not `ACP_STOP_CANCELLED`);
  2. "run `echo hi > created.txt` with Bash" → no file; the request, if made, is a `decidedBy: "profile"` denial (the project allow rule is not loaded);
  3. the embedder tool runs without a permission request;
  4. a read ("list the files here") works.
  Record the cost and any `decidedBy: "profile"` denials (counted, not required). #2364 and #2367 are covered by the fake agent only, by design: neither failure can be triggered on demand against Claude.
- **Gates** at the repo root: `bun run typecheck`, `bun run check:all`, `bun run test`; plus `bun run check:api` in `packages/nax-agent`.
